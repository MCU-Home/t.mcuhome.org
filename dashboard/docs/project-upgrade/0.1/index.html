The dashboard cannot open this project

For dashboard version 0.1. MCUHome is pre-1.0 — details may still change between minor versions.

A project directory states which layout it uses, in the file .mcuhome-project-root at its root. The dashboard opens a project that already exists; it does not create or upgrade one. When the project states a layout the dashboard does not speak, it lists no devices and says so, rather than showing you devices that every action would then refuse.

Which of these you are looking at decides what to do.

“The project was written by older tools”

The project needs to be upgraded, and something other than the dashboard has to do it.

Home Assistant App

You should not see this. The App upgrades the project when it starts, so restart the App first. If it comes back, the upgrade is failing — check the App's log, which says which migration stopped and why.

Running the dashboard yourself

Upgrade the project with the MCUHome command line, which is a separate program you install once:

pip install mcuhome
mcuhome project upgrade /path/to/project

Back the project up first — commit it to git, or copy the directory. An upgrade rewrites files in place and cannot be undone. Stop the dashboard while it runs. The command shows what it will change and asks you to type yes before it does anything.

The command line's own page has the detail, including how to confirm without a terminal and what to do if an upgrade is interrupted: Upgrading a project.

“The project was written by newer tools than these”

The project is ahead of the dashboard, and a project is never downgraded. Update the dashboard — or, in Home Assistant, the App — to a version that understands it. Until then, use the machine or the tools that wrote the project.

“An upgrade is working on this project”

An upgrade renames the project file to .mcuhome-project-root.upgrade while it holds the project, so this means one is either running right now or was killed halfway.

If one is running, wait for it. If nothing is running, it was interrupted and the project is half-migrated: restore your backup and upgrade again. MCUHome deliberately does not try to repair a partly applied migration, because it cannot know what was already done.

“The project file cannot be read”

The marker file is missing, unreadable or not valid. Check the directory the dashboard names. Do not edit .mcuhome-project-root by hand — MCUHome maintains it, and a wrong value there makes the project unusable. Your own settings live in mcuhome.yaml next to it.
