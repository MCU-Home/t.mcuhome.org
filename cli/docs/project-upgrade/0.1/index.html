Upgrading an MCUHome project

For CLI version 0.1. MCUHome is pre-1.0 — commands and flags may still change between minor versions.

A project directory states which layout it uses, in the file .mcuhome-project-root at its root. When MCUHome moves past that layout, every command refuses to touch the project until it has been upgraded:

The project in "/home/you/my-home" needs an upgrade (project version 0, expected 1).
  Fix: back the project up first, then upgrade it:
    mcuhome project upgrade /home/you/my-home

Before you upgrade

  • Make a backup. Commit the project to git, or copy the directory. An upgrade rewrites files in place and cannot be undone.
  • Stop anything else that is using the project — a build in another terminal, an editor that writes into it. The upgrade waits for builds it can see, but it cannot see everything.
  • Run mcuhome project upgrade --dry-run first if you want to read what will change without changing anything.

Running it

mcuhome project upgrade            # the project you are standing in
mcuhome project upgrade /path/to/project

The command shows what it will do and asks you to type yes. In a script, where there is nobody to ask, confirm by naming the project instead — its id, or the short form mcuhome project info prints:

mcuhome project upgrade /path/to/project --confirm-upgrade a9e005

Naming the project rather than passing a general "force" flag is deliberate: a script that ends up in the wrong directory then refuses instead of migrating something else.

Stopping an upgrade

Press Ctrl+C and the upgrade finishes the step it is on, then stops cleanly — the project is left at the version it reached, and running the upgrade again continues from there. Pressing Ctrl+C three times within three seconds aborts immediately, which will most likely leave the project broken.

If an upgrade was interrupted

If a migration failed, or the process was killed outright, the project file stays renamed to .mcuhome-project-root.upgrade and every command says:

The upgrade of the project in "/home/you/my-home" was interrupted.

The project is in a half-migrated state. Restore your backup and run the upgrade again — MCUHome deliberately does not try to repair a partly applied migration, because it cannot know what was already done.

What the project file holds

version = 1
id = "0198f5c2-9c41-7a3e-8b6d-2f7c14a9e005"

The version is the layout the project uses. The id is drawn once, when the project is created, and never changes; it belongs to the project, so keep the file in version control and a clone of the project stays the same project.

Do not edit this file by hand. MCUHome maintains it, and a wrong value there can make the whole project unusable. Your own settings live in mcuhome.yaml next to it.
